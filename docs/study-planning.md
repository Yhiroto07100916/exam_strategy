# AI学習計画機能 設計

## 目的

模試の科目別成績・問題別の単元正答率・科目別目標点を根拠に、受験日までの月間目標を作り、週間目標・日々の学習タスクへ自動分解する。高校受験モードと大学受験モードのデータは既存の受験モード分離を維持する。

## UX

### 1. 初回設定

- 目標日（受験日・模試日など）
- 学習可能な曜日と曜日ごとの上限時間
- 1回あたりの標準学習時間（既定50分）
- 休息日・予定変更日
- 既存の志望校/大学・科目別目標点を初期値として参照。未設定ならユーザーに目標点を強制せず、現状改善型の計画として生成する

### 2. 自動生成結果

階層は「全体 → 月間 → 週間 → 日間」。

- 全体：対象期間、利用可能時間、重点科目、計画の前提・データ不足
- 月間：月ごとの到達目標、重点単元、目標学習時間、月末チェック
- 週間：科目別・単元別の到達目標、週の学習時間、週末の確認テスト
- 日間：具体的なタスク、所要時間、教材/取り組み方、完了状態

### 3. 継続運用

- タスクの完了・未完了・スキップと実績時間を記録
- 未完了タスクは自動で翌日に詰め込まず、残り期間と空き時間を見て再配分案を提示
- 週次レビューで計画時間と実績時間、単元の変化、次週の調整案を表示
- 再生成時は既存計画を上書きせず、版を作成して比較・切り替え可能にする

## 成績・弱点からの優先度

初期版は説明可能なスコアリングを使用し、生成結果に根拠を付ける。

- 単元の弱さ：問題別データの正答率/得点率。記録数が少ない場合は「暫定」と表示
- 科目の現状：直近の模試成績。異なる試験の満点や難易度を単純な素点で比較しない
- 目標との差：設定済み科目別目標点がある場合のみ計算。学校別配点や合格可能性を推測しない
- 学習機会：対象期間と曜日別の学習可能時間
- 分散：苦手科目だけに偏らず、復習・演習・定着確認を含める

同日同科目に複数試験があり最新成績を一意に決められない場合は、その成績を確定値として扱わず、曖昧であることを表示する。

## AIの役割と安全策

- AIはタスクの具体化、学習方法の言語化、週次レビューの要約に使う
- 時間配分・日付・合計時間・上限・重複防止はサーバー側の決定的ロジックで検証する。AIの出力をそのままDBへ保存しない
- AI出力はJSONスキーマで検証し、期間外の日付、利用可能時間超過、未知の科目/単元、極端な学習量を拒否または修正する
- APIキーは環境変数で管理し、ブラウザへ返さない。未設定時も計画生成が使えるよう、ルールベース生成へフォールバックする
- AIが出した目標や学習時間は提案であり、成績向上・合格を保証しない
- 個人情報はプロンプトへ含めず、必要な成績要約だけを渡す

## データモデル案

### study_plans

- id (UUID, PK)
- title
- start_date / target_date
- status (active / archived)
- version
- generation_mode (ai / fallback)
- source_snapshot_json（生成時の成績・目標・弱点の要約）
- plan_json（月/週/日階層）
- created_at / updated_at

### study_task_progress

- id (UUID, PK)
- plan_id (FK)
- task_id（plan_json内の安定ID）
- status (pending / completed / skipped)
- actual_minutes
- note
- completed_at / updated_at

計画の再生成時に過去の進捗を失わないよう、計画本体は版管理し、進捗はplan_idとtask_idに紐付ける。

## API案

- GET /api/study-plans：計画一覧
- POST /api/study-plans/generate：入力条件と既存データから新しい計画を生成・保存
- GET /api/study-plans/{plan_id}：月/週/日の計画と進捗
- PATCH /api/study-plans/{plan_id}/tasks/{task_id}：進捗更新
- POST /api/study-plans/{plan_id}/review：週次レビューと次週の再配分案
- POST /api/study-plans/{plan_id}/archive：計画をアーカイブ

全APIは既存の X-Exam-Mode によるDB分離に従う。

## 実装フェーズ

1. **基盤**：DBテーブル、入力検証、計画生成エンジン、API、単体/APIテスト
2. **画面**：初回設定、月/週/日ビュー、タスク進捗、モバイル表示
3. **AI接続**：環境変数によるAIプロバイダー設定、構造化出力、タイムアウト/失敗時フォールバック
4. **改善**：週次レビュー、未完了タスク再配分、計画バージョン比較

## MVPの受け入れ条件

- 高校受験/大学受験のデータが混ざらない
- 成績・弱点・目標のどのデータを根拠にしたか確認できる
- 月間目標から週間・日間タスクまで日付と時間が整合する
- 曜日別の可処分時間を超えない
- 成績がない/弱点データが少ない場合も生成でき、推定の限界を明示する
- 既存の成績・問題・目標・バックアップの挙動を壊さない

## AIプロバイダー設定

AIによるタスク文面の具体化には、サーバー側に次の環境変数を設定します。

- `STUDY_PLANNER_API_KEY`：OpenAI互換Chat Completions APIのキー
- `STUDY_PLANNER_BASE_URL`：APIのベースURL（既定値 `https://api.openai.com/v1`）
- `STUDY_PLANNER_MODEL`：利用モデル（既定値 `gpt-4o-mini`）

APIキーはサーバー内だけで使用し、ブラウザへ返しません。送信する情報は科目・単元・集計済み正答率・問題数など計画生成に必要な要約に限定し、氏名やアカウント情報は送信しません。AIはタスク名と学習方法の文章だけを提案し、日付・学習時間・科目・単元・タスクIDは変更できません。APIキー未設定、タイムアウト、応答形式不正の場合は標準計画へフォールバックします。


## 週次レビューと再計画

- `POST /api/study-plans/{id}/review` は週単位の完了率、予定/実績時間、科目別進捗、次週への提案を返す
- `POST /api/study-plans/{id}/replan` は未完了タスクを指定日以降の曜日別空き時間へ再配置する
- 完了・スキップ済みタスクは元の日付と進捗を維持する
- 空き時間が足りない場合はHTTP 409で中断し、元の計画を変更しない
- 再計画は元計画をアーカイブし、親計画IDとバージョン番号を持つ新しい計画として保存する

## バックアップ

既存のJSONバックアップ形式 version 1 に `study_plans` と `study_task_progress` を追加した。旧バックアップではこれらの配列が空として扱われるため、既存データの復元との互換性を維持する。復元時には計画ID、タスク参照、進捗状態を検証し、トランザクション内で置き換える。
